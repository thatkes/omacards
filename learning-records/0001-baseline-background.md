# Baseline: new maintainer, general programmer, new to Qt

The user is onboarding as a maintainer of omacards. They are a competent
general programmer but new to Qt/QML, so lessons must define Qt concepts on
first use (QObject, context properties, qmake, qrc paths, offscreen platform)
rather than assuming them. Their goal is confident, tested changes to the code,
not abstract familiarity. No fixed time budget per lesson; keep them short
anyway. This sets the floor for lesson planning: domain and architecture can be
taught directly, Qt mechanics need scaffolding.

Evidence: stated directly when the teaching workspace was set up.

Implications: do not re-teach general programming concepts; do pair every
Qt-specific claim with an official doc citation from [[RESOURCES.md]].
